# anima 与潜知识基底

[English](TACIT-KNOWLEDGE.md) | [中文](TACIT-KNOWLEDGE.zh-CN.md)

## 1. 问题

许多项目失败，并不是因为缺少代码、文档或工具，而是因为真正决定成败的知识没有进入智能体可感知的环境。

这些知识通常不是显性的 API 说明，而是：

- 为什么当初选择了这条路径，而不是另一条路径。
- 某个看似奇怪的约束背后，曾经踩过什么坑。
- 哪些判断标准只存在于资深成员的经验中。
- 什么事情理论上可行，但在本组织、本业务、本数据、本代码库中不该这样做。
- 当冲突出现时，团队实际如何权衡速度、质量、成本、安全和可维护性。

这些就是项目中的 **潜知识**。人类可以通过长期共事、口耳相传和反复踩坑获得它；智能体如果只能读取当前任务描述和局部代码，就会不断犯同一种错误。

anima 的目标不是替代人类经验，而是让这些经验逐渐沉积到仓库中，成为智能体可读取、可遵循、可继续改进的环境。

## 2. 潜知识为什么难以传承

潜知识有三个特征。

**它常常在事后才被意识到。** 团队很少会在项目第一天就完整写出所有规则。真正重要的规则，多半来自事故、返工、争论和一次次选择。

**它依附于具体语境。** 泛化的最佳实践只能给出方向，不能替代本项目的历史。一个量化系统、一个具身数据生产系统、一个企业内部知识库，虽然都需要 agent，但它们真正的禁区、偏好和判断标准完全不同。

**它会随项目演化。** 旧的约束可能过时，新的模式可能出现。把知识写成一次性的静态文档，只会很快变成负担。

因此，解决潜知识问题不能只靠“写一本手册”。更合理的做法是建立一种持续沉积机制，让知识在实践中被发现、记录、验证、修剪和重新组织。

## 3. anima 的定位

anima 可以被理解为项目的 **潜知识基底**：它把 agent 工作所需的背景、记忆、决策和反馈回路放进仓库，使每一次协作都能为下一次协作改善环境。

这与传统模板不同。

模板试图在项目开始时一次性给出正确结构。anima 只播下一颗种子：`AGENTS.md`、`docs/ARCHITECTURE.md` 和 `docs/decisions/`。这些文件一开始不需要完美，它们的价值在于承接后续实践中长出来的知识。

当 agent 发现一个重要决策，它应当记录到决策文档中。

当 agent 反复遇到某类错误，它应当建议把经验提升为测试、linter、类型约束或运行时检查。

当 agent 理解到架构发生变化，它应当更新架构文档，而不是只完成眼前代码。

当旧知识不再成立，它应当被修剪，而不是继续误导后续会话。

## 4. 从“提示词”到“环境”

很多 agent 落地问题表面上像提示词问题，本质上是环境问题。

提示词只能告诉智能体“现在该怎么做”。环境则告诉智能体“这个项目一贯如何思考、如何判断、如何避免重蹈覆辙”。

如果潜知识只留在人脑中，那么每个新会话都会退化成一次冷启动。人需要不断解释背景，agent 需要不断重新试错。anima 试图改变这一点：让项目本身成为记忆，让仓库承担一部分组织学习能力。

这也是 harness engineering 的关键：不是把智能体关在更复杂的规则笼子里，而是为它提供更丰饶、更真实、更能反馈的工作环境。

## 5. 适用场景

anima 不只适用于企业内部工程项目。任何存在长期协作、隐性判断和持续演化的项目，都可能需要潜知识基底。

### 软件工程

代码库的关键知识往往不在函数签名中，而在架构取舍、历史债务、边界条件和团队约定中。anima 让这些知识逐渐进入 agent 的工作面。

### 企业 agent 落地

企业中的大量流程依赖老员工经验：客户偏好、交付边界、异常处理方式、质量标准、合规红线。agent 如果无法感知这些知识，就只能做表层自动化。anima 提供一种把经验沉积为可执行环境的方式。

### 具身数据生产

具身智能的数据生产包含大量难以一次性写清的判断：什么样的数据有价值，什么样的仿真分布可信，哪些标注规则会污染训练，哪些异常值得保留。anima 可以帮助团队把这些判断从人脑迁移到项目记忆中。

### 量化研究

量化系统中的经验教训通常来自失败的策略、数据源异常、回测偏差和风险事件。anima 可以把这些经验转化为策略生命周期、验证门禁、风险约束和研究日志的一部分。

### 个人知识库

个人知识管理也有潜知识问题：为什么某个主题重要，某条笔记如何与长期问题相连，哪些材料已经被验证或放弃。anima 的种子思路可以帮助 agent 与知识库共同生长。

## 6. 最小实践

在一个新项目中，使用 anima 解决潜知识问题不需要复杂系统。可以从四个习惯开始：

1. **决策即记录。** 只要做了影响未来维护的选择，就写入 `docs/decisions/`。
2. **重复错误即机制。** 同类错误出现多次，就把它升级为测试、lint、类型约束、脚本或检查命令。
3. **理解变化即更新架构。** 当 agent 或人类对系统结构有了更准确认识，就更新 `docs/ARCHITECTURE.md`。
4. **过时知识即修剪。** 文档不是越多越好；错误、陈旧、无用的知识应当被删除或改写。

这四个习惯的重点不是文档洁癖，而是让项目在每一轮协作后变得更适合下一轮协作。

## 7. 判断标准

一个 anima 项目是否真正沉积了潜知识，可以看几个信号：

- 新 agent 会话能更快理解项目，而不是反复询问同样背景。
- 重要决策能追溯到当时的语境，而不是只剩结果。
- 常见错误逐渐被机械机制拦截，而不是依赖人记住。
- 文档描述的是项目真实状态，而不是模板化愿望。
- 项目越发展，agent 的有效行为越像熟悉该项目的成员。

如果这些信号出现，说明 anima 不只是在生成文件，而是在帮助项目形成可传承的记忆。

## 8. 结论

潜知识不是一次性整理出来的资产，而是在行动、反馈和修剪中长出来的环境。

anima 的核心价值，是让项目不再把智能体当成每次都要重新培训的外部工具，而是让项目自身逐渐长出能被智能体读取的记忆、身份和判断力。

这就是“种子”区别于“模板”的地方：模板给项目一个起点；种子让项目拥有生长出自己经验的能力。
